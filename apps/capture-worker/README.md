# Capture worker

使用固定的 `desktop-1920` 設定保存首屏、完整頁面、文字摘要與同站內頁候選。真實網站的版本差異門檻必須經樣本校正後才能啟用。

## 擷取規則

- 瀏覽器 viewport(可見區域)固定為 1920 × 1080，`deviceScaleFactor` 固定為 1。
- 產生完整頁面截圖前，先逐段捲動到頁尾，觸發 lazy loading(延遲載入)、`IntersectionObserver` 與捲動動畫。頁尾高度連續三次不再增加才開始擷取。
- 完整頁面由多個實際捲動後的 `1920 × 1080` 視窗合成，不使用瀏覽器的一次性 `fullPage` 截圖。後者無法正確保存捲動驅動動畫，會留下有高度但沒有內容的區段。
- 首屏與每一段截圖前，除了最短停留與圖片等待，還要等到目前可見區域畫面穩定（含較高解析指紋、欄／列差異，以及照片帶上的局部 wipe，不只整欄平均）；不可用 `prefers-reduced-motion` 跳過動畫。
- 截圖前會關閉或隱藏阻擋畫面的隱私／Cookie 同意層；有拒絕、僅必要或關閉控制時優先使用，不接受行銷 Cookie。
- 第一段以外會隱藏頁首已存在的固定元件、透明的固定殼（以及殼裡的導覽鈕）、小型頂部 sticky 導覽列，以及貼齊左右的 sticky 側欄。接近全寬的 sticky 捲動場景與真正的虛擬捲動畫布仍保留。蓋滿視窗但透明、不接收指標、也沒有大型 canvas／影片的 fixed 層不是虛擬畫布。虛擬畫布上仍像 wipe 的視窗不寫入；跟捲動綁死的半完成揭示要微移或略過，不可把逾時幀當成品。同一幕若先寫入 wipe、後寫入乾淨幀，留下乾淨的那張。後段開頭若與前一段**空間**高變異內容重複則裁掉，只剩碎帶則整段丟掉；wipe 幀對下一張乾淨卡也算同一張。整張照片卡上下堆疊（週期含 1080 視窗；先比對齊的相鄰 viewport 磚，沒命中再滑動 1080，並用左／右半幅比照片；百葉窗蓋住上半時不可因頂部樣本不足而拒裁，384 指紋上淡化成 165–200 的直欄也要略過；wipe 磚頂部若還留上一張褶衣一截，左半主照片對得上仍要裁；拼接步進造成的重疊堆疊週期可短於 1080，同一個裁切裡上半 wipe 下半乾淨時也要裁上複本；上複本常帶 wipe，即使粗指紋沒掃到三條也要用遮罩差（含亮舞台／暗牆紙）；可從 y=0 裁；中段上方可以是另一張作品卡）與 12px–五分之一 viewport 的接縫腰帶都要裁；虛擬畫布成品也要跑這道去重。細帶用一維列指紋並分左／右半幅，不能在 14k 長圖上做二維細掃描，也不能只掃 10–22% 或要求 lower 上方再空兩個視窗高。暗照片腳帶若底下已是留白，即使與上方 luma 幾乎一樣也要裁。Wipe 鄰欄在暗牆紙與亮舞台另走高彩度，一般 45–175 不變以免大標題誤判。飽和純色不當成場景帶。釘住的同一張虛擬畫布照片只留一幕。
- 圖片逾時或載入失敗時仍保留瀏覽器呈現的結果。存取驗證頁、頁面持續增加內容、超過高度上限、合成區段不完整、文件流成品高於文件高度，或接縫重複 20% 重疊帶時，整個工作失敗，不寫入不完整原圖。捲動鎖定的單屏頁要保存目前視窗。
- 完整頁面原圖不得自動裁掉大面積白色、灰色或純色區塊。這些區域可能是網站刻意安排的留白、背景或內容節奏；自動刪除會讓保存結果與原網站不一致。
- 列表使用另外產生的低解析度預覽圖，完整高解析度原圖必須保留，不能由預覽圖覆寫。

修改擷取流程前，先讀 [`doc/capture-rules.md`](../../doc/capture-rules.md) 的實作檢查清單。那一節寫明同意層、重複 chrome、動畫穩定、必須失敗與禁止網域特例；對應程式在 `src/capture.ts`，對應測試在 `tests/capture/capture.test.ts`。
